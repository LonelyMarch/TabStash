TabStash is a side-panel extension for Microsoft Edge and Google Chrome. It displays your open windows, tab groups, and tabs in a window tree. You can archive an entire window locally and restore it later.

Archives preserve tab order, pinned tabs, tab groups, and the active tab. For regular web pages, TabStash also makes a best effort to save scroll positions and native audio and video playback positions. Archives stay in your browser's local storage; no account or cloud service is required.

## Features

- **Live window tree:** Browse windows, tab groups, and tabs; activate tabs and switch windows.
- **Window archiving:** Save a window manually, with the option to close it afterward. Automatic archiving of closed windows is off by default.
- **Archive management:** View, pin, unpin, and delete archives. Restoring can keep the archive or remove it after the window structure has been fully restored.
- **Page progress:** Best-effort restoration of top-level and inner scroll positions and native HTML media playback positions on regular web pages. Media does not autoplay after restoration.
- **Appearance and keyboard navigation:** Edge- and Chrome-specific styling, automatic/light/dark appearance modes, and keyboard navigation in the window tree.
- **Multiple languages:** Arabic, Simplified Chinese, English, French, Russian, and Spanish. The interface follows the browser language by default; you can change it at the bottom of the side panel.

## Quick Start

You need **Node.js 22+** and **pnpm 11**. Install dependencies and build the version for your browser from the repository root:

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm build:chrome
```

Enable **Developer mode** on your browser's extensions page, then choose **Load unpacked**:

| Browser | Extensions page | Directory to load |
| --- | --- | --- |
| Microsoft Edge | `edge://extensions` | `.output/edge-mv3` |
| Google Chrome | `chrome://extensions` | `.output/chrome-mv3` |

Click the TabStash toolbar icon to open the side panel. After changing development code, rebuild the extension and click **Reload** on the extensions page. Archives belong to the current extension instance's local storage; removing that instance may erase its data. Development and production directories may have different extension IDs, so their local data can be separate.

## Usage

| Action | Behavior |
| --- | --- |
| Archive | Click the archive icon on a window row to save the window while keeping it open. |
| Archive and close | Save the window, then request that the browser close it. Any browser close confirmation still requires your input. |
| Automatic archiving | Enable it under **Settings** at the bottom of the side panel. It uses the last successfully saved window snapshot before closure. |
| Restore | Choose **Restore** to keep the archive or **Restore and remove** to remove it only after the window structure has been fully restored. |
| Manage archives | Pin, unpin, or delete an archive. Deletion cannot be undone in the extension. |

With focus in the side panel, use `Tab` / `Shift + Tab` to switch between regular windows. Press `F6` to reach settings and other controls; `F6` or `Esc` returns to the window tree. Within the tree, use the arrow keys and `Home` / `End` to navigate.

## Development and Verification

```powershell
pnpm dev:edge
pnpm dev:chrome
pnpm typecheck
pnpm lint
pnpm test
```

To update the README screenshots, build the Edge extension first and then run `pnpm capture:readme`. The script uses only an isolated browser profile and local test pages.

If WXT cannot find your local Edge installation, create an untracked `web-ext.config.ts` and set `binaries.edge` to the browser executable. This file is listed in `.gitignore`.

End-to-end tests use real browsers, isolated browser profiles, and production builds. They require a Windows environment that can launch graphical browsers. Build both browser versions first, then run:

```powershell
pnpm install:chrome-test
pnpm test:e2e
```

`install:chrome-test` downloads a pinned Chrome for Testing version into the ignored `.tmp/` directory and verifies its SHA-256 checksum. The GitHub Actions workflow is at [`.github/workflows/ci.yml`](./.github/workflows/ci.yml).

## Release Packages

Create separate ZIP files for Edge Add-ons and the Chrome Web Store:

```powershell
pnpm zip
pnpm zip:chrome
pnpm check:package
```

The output files are `.output/tabstash-<version>-edge.zip` and `.output/tabstash-<version>-chrome.zip`. `check:package` verifies production permissions, entry points, assets, and ZIP headers for both browsers, then writes checksums to `.output/SHA256SUMS.txt`. Git ignores `.output/`. You can attach both ZIP files and the checksum file to a GitHub Release and submit the matching ZIP to each store. Production packages do not require a development server.

## Data and Permissions

| Permission | Purpose |
| --- | --- |
| `tabs`, `tabGroups` | Read tabs and groups in each window and reconstruct them during restoration. |
| `sidePanel` | Open the side panel from the toolbar action. |
| `storage` | Store settings, a session identifier, and short-lived operation state. |
| `favicon` | Retrieve browser page icons. |
| `<all_urls>` | Track scroll and native media progress on top-level regular web pages. |

Archives, window snapshots, and page progress are stored locally in IndexedDB. Settings are stored in browser extension storage. The extension does not read form values, page body text, or login credentials, and does not upload archives to a remote service. Page progress applies only to accessible regular web pages; restored media does not autoplay.
